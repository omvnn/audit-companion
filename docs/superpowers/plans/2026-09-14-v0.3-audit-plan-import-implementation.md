# Audit Plan Import v0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy an import-first audit creation flow that accepts PDF/JPG/PNG audit plans, rejects unreadable pages, extracts exact inspection rows and methods, stages them for one review screen, and promotes the approved plan into an operational audit with source traceability.

**Architecture:** Keep the production app frontend-first. Run deterministic document quality checks and OCR/table parsing in the browser so company document content is not sent externally by default; persist staged imports/pages/items in Supabase with RLS. AI fallback remains a server-side/provider adapter boundary that is disabled until an approved provider is configured, and the UI must fail closed with explicit guidance rather than sending data from the browser. Promotion into `audits`, `audit_members`, `checklist_items`, and `audit_sources` is transaction-safe through a narrow authenticated RPC.

**Tech Stack:** Existing Vite 6 + vanilla ES modules + Supabase Auth/Postgres/PostgREST/Storage + AppDeploy. Browser OCR: Tesseract.js 6.0.1 loaded from a version-pinned CDN only during import; PDF rendering: pdfjs-dist 4.10.38 loaded from a version-pinned CDN. No company document bytes are uploaded to those CDNs; OCR executes locally in the browser. Supabase stores source files privately.

**Spec:** `docs/superpowers/specs/2026-09-14-v0.3-audit-plan-import-design.md`

## Global Constraints

- Import/Scan is the default audit-creation path; `Create manually` remains available as fallback.
- Preserve exact inspection-item wording and row order; repeated clauses remain distinct rows.
- Do not create an operational audit until the user presses **Create Audit** on the review screen.
- Blurry/cropped/glare/low-confidence required content must fail closed and request reupload; never silently guess.
- Multi-page imports preserve good pages and allow replacing only failed pages.
- Deterministic OCR/table extraction is primary; AI fallback is secondary and disabled until an approved provider is configured.
- AI output, when later enabled, remains untrusted structured input and may never create an audit directly.
- Uploaded plans remain private; signed links are short-lived; no service-role/provider secret is exposed client-side.
- Current production stays v0.2.0 until v0.3 implementation, migration, security checks, browser QA and merge all pass.
- The user's real company audit-plan images must not be committed as fixtures.
